# Kalimba

Standalone static route: `/kalimba`. One instrument-centred screen, designed for phone portrait and responsive desktop use. No account, server, uploads, or sync.

## Flow

- First visit: load existing IndexedDB keys with no tine selected. Tap a key to highlight its full length and open an accessible recording dialog: a bottom sheet on phones and a centred modal on desktop. The dialog shows the key, saved note, input wave, capture indicators, and pitch-consistency feedback. Dismissing it stops capture and clears selection.
- Save & next stores a key before advancing to the next missing key in the same dialog. Saving the final missing key automatically chooses the first playable starter song; if none fits, it opens Free play. It never autoplays or starts another microphone session.
- Returning visit: restore the recorded instrument and last chosen song or Free play. Tempo, looping, and practice mode are also remembered under `kalimba-preferences-v2` in localStorage.
- The song picker is the only main control outside the face. Listening, demonstration playback, and restart are on the instrument. Settings is in the header; setup progress is above the instrument and in the recording dialog. Free play uses the same face without song cues.
- Settings contains key editing, practice options, and backup/restore. Key editing preserves the old recording until its replacement is accepted. Record all keys walks through all nine even when they already have saved recordings.
- Dialog sheets use Radix for focus trapping, Escape handling, and accessible titles.

## Audio and storage

The IndexedDB schema and backup format remain `kalimba-local-v1` / backup version 1, preserving recordings from the previous interface. Keys are numbered 1–9 from the player's left.

Setup records up to 22 seconds per key using a browser-supported MediaRecorder format. A 700 ms room-noise check sets a local input threshold; recording finishes automatically once three matching plucks are found, allowing up to six attempts while keeping earlier good plucks (or can be finished manually after three attempts). Clipping and quiet-input feedback guide the capture. Local YIN analysis requires two reference plucks within 30 cents plus a third within 65 cents of their midpoint. The displayed percentage is a heuristic pitch-consistency score (100 minus 0.23 times the cents difference), not waveform identity or a probability of correct identification. It ignores loudness, chooses the best matching three across six attempts, and ignores unrelated frames or drifting tails when enough stable frames remain. Six attempts without a matching set require a restart. Playback trims a mono WAV of up to 1.5 seconds from a chosen matching pluck, avoiding a discarded initial attempt. Duplicate full notes (including octave) or near-identical measured frequencies cannot be assigned to another key; manual edits and restored backups use the same guard. Re-recording the same key remains allowed. Each accepted key is saved atomically. The measured frequency drives recognition independently of its editable musical note label.

AudioWorklet performs pitch, FFT, and attack analysis on the audio rendering thread. Live analysis uses a 4096-sample window with a 512-sample hop (~11 ms at 48 kHz); calibration uses a 1024-sample hop and downsamples by two for YIN. These hop sizes are analysis cadence, not end-to-end latency promises. The worklet has silent output connected to the destination for Safari; microphone sound is never played back. Older browsers without AudioWorklet use the same analysis engine on a 22 ms compatibility timer. Worklet assets are generated by `predev` / `prebuild` from the shared source modules.

Saved keys now optionally include a harmonic profile and estimated half-amplitude decay. Existing recordings continue to work without profiles; re-recording adds them. Live detection scores fresh fundamental/harmonic energy, uses the learned profile when available, confirms two frames without switching candidates halfway, and uses separate global (45 ms) and adaptive per-key (85–120 ms) retrigger guards. No pitch analysis runs during live recognition of calibrated keys. Ringing alone should not trigger practice, but overlapping notes remain more difficult than isolated plucks; this is not a chord recogniser. Duplicate pitches cannot reliably identify a physical tine. Live practice never plays accompaniment. Microphone tracks and worklet ports stop on tab hiding, cancellation, settings opening, or unmount. Phone microphone use requires HTTPS.

Songs are short beginner arrangements. Exact semitone transposition is attempted against recorded keys; missing notes are never substituted. The requested popular themes are simplified opening motifs. Add arrangements to `music.mjs`.

Browser storage may be evicted or cleared. JSON backups contain audio samples; restore atomically replaces the instrument.

## Visuals

The revised instrument is custom face-on SVG with the photographed tapered tines, staggered upper ends, circular retaining bar, thin fulcrum, arched, tapered face marking, almond eyes, and large sound-hole rim. It keeps the established paper/green palette and numbers on metal tips. Regenerate its static payload with `node scripts/kalimba/build-art.mjs`; refresh the gallery thumbnail with `node scripts/kalimba/thumbnail.mjs`. SVG paths are passed from the server page to the interactive component. No drawing library ships to the phone.

Inter / EB Garamond, thin rules, neutral paper, and restrained controls reference `https://skills.wheresryan.sh/anatomy`. It is an adaptation, not a pixel-identical copy of that site. The user's request for a face-on instrument supersedes the earlier isometric direction.

## Validation

- `node --test scripts/kalimba/*.test.mjs` — tests for pitch, mixed-note attacks, harmonics, repeated plucks, noise, duplicate rejection, calibration consistency, cancellation, PCM samples, onboarding progression, song selection, and compatibility. Streaming tests exercise the actual FFT/analysis engine with rapid alternating notes and long decays; worklet tests verify forwarding and cancellation during module loading.
- `npx eslint --config scripts/kalimba/eslint.config.mjs src/features/kalimba src/app/kalimba` — includes JSX, which the repository's default lint configuration skips.
- `npm run lint` and `npm run build` — production static export.

Browser checks: first visit with no keys, existing nine-key instrument, settings and song sheets, Free play persistence, manual note correction and saving, repeated-note practice progression, and demonstration cancellation. Narrow phone (320px), iPhone-sized (402px), and desktop (1440px) layouts were checked for sideways overflow. Existing generated test recordings remain compatible. Physical iPhone microphone accuracy still needs testing with the user's kalimba; synthetic tests do not establish it.

Accuracy checks use deterministic synthetic signals and spectra, including softer new notes over lingering louder notes and 150 ms same-key re-plucks. These establish algorithm behaviour, not real-world phone accuracy or chord support. Final tuning must use real recordings from the target phone. Forgiving-setup tests additionally cover a third pluck at 85–90% consistency, extra attempts, unrelated notes, octaves, discarded samples, modal selection/dismissal, and 320/402/1440px layouts.
